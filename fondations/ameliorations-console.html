Composants pour les consoles de gestion ​

Ces API répondent aux besoins observés dans DevHub. Elles sont implémentées dans les sources SIA UI ; le changeset prépare leur publication. Une application installée sur une ancienne version ne les reçoit pas avant la publication et la mise à jour de ses dépendances ou de ses composants copiés.

Actualiser une liste ​

DataTable affiche une action d'actualisation lorsque onRefresh est fourni. Aucun bouton n'est ajouté aux usages existants. showRefresh={false} le masque. refreshButtonProps permet de régler le texte (children), l'icône (leftIcon), la taille, la variante, l'infobulle, le nom accessible et la désactivation.

tsx
<DataTable
  columns={columns}
  data={query.data ?? []}
  loading={query.isPending}
  refreshing={query.isFetching && !query.isPending}
  onRefresh={() => {
    void query.refetch();
  }}
  refreshButtonProps={{ children: "Synchroniser", variant: "outline" }}
/>

refreshing conserve les lignes et désactive le bouton pendant l'appel ; loading reste l'état de chargement initial. Le bouton reste disponible sur une liste vide ou en erreur. Le consommateur gère la requête, son état et ses erreurs : SIA UI ne dépend pas de TanStack Query. Le libellé par défaut suit locale.dataTable.refresh (français/anglais) ; son nom accessible reste stable pendant le chargement.

CrudPage transmet onRefresh et refreshing. Les réglages passent par table={{ showRefresh: true, refreshButtonProps: { children: "Recharger" } }} ; les props explicites de table gardent leur priorité.

Permissions par domaine ​

PermissionMatrix prend des groupes { domain, label, actions: [{ action, label }] } et une liste de permissions. Les valeurs sont ${domain}.${action}. Elle se branche avec value/onValueChange, ou defaultValue si elle gère son état localement.

  • La case de domaine reflète la sélection partielle. Avec allowWildcard (par défaut), elle sélectionne domain.*, y compris les futures actions ; les cases individuelles restent alors verrouillées jusqu'au retrait du joker.
  • allowWildcard={false} sélectionne seulement les actions connues. Un joker préexistant reste affiché et verrouillé : ce mode ne le transforme pas silencieusement.
  • canGrant(permission) verrouille les droits non accordables. Un joker ne peut être accordé que si le joker et toutes les actions présentées sont accordables. Les valeurs inconnues sont conservées.
  • disabled verrouille tout. Le joker global * est affiché en lecture seule ; sa gestion appartient au flux super administrateur de l'application.
  • Les libellés métier viennent de l'application ; « Tout le domaine » vient de locale.permissionMatrix.all. checkboxProps règle l'apparence des cases.

Le serveur reste responsable de l'autorisation : ces contrôles d'interface ne remplacent pas la vérification des droits de celui qui modifie un rôle.

Contrôles de formulaire personnalisés ​

Field, FormFieldConfig et ResourceField acceptent type: "custom" et renderControl. Le callback reçoit name, value, onChange, onBlur, disabled, required et error. Il retourne un élément React ; un composant personnalisé doit transmettre à son élément racine les attributs id et aria-* reçus. Field relie ainsi le contrôle au libellé, à l'aide et à l'erreur. Le callback doit brancher les changements et la sortie du contrôle. Les valeurs restent celles de FieldValue, notamment string[] pour les permissions.

tsx
const roles = defineResource({
  name: "roles",
  fields: {
    permissions: {
      type: "custom",
      label: "Permissions",
      defaultValue: [],
      inTable: false,
      renderControl: ({ value, onChange, onBlur, disabled }) => (
        <PermissionMatrix
          groups={groups}
          value={Array.isArray(value) ? (value as string[]) : []}
          onValueChange={onChange}
          onBlur={onBlur}
          disabled={disabled}
          canGrant={canGrant}
        />
      ),
    },
  },
});

Le formulaire dérivé conserve la validation et désactive le contrôle pendant l'envoi. renderControl ne remplace pas ResourceField.render, qui sert aux cellules du tableau et à la vue de détail. children reste prioritaire lorsqu'un contrôle est passé directement à Field. Un champ personnalisé sans renderControl ni children est une erreur explicite.

Conventions CRUD configurables ​

permissions: "auto" garde les verbes français existants. Pour une API qui utilise read/create/update/delete, le domaine peut différer du nom de la ressource :

tsx
permissions: {
  domain: "provider_accounts",
  verbs: { view: "read", create: "create", edit: "update", delete: "delete" },
}

createPermissionConvention(verbs) retourne une fonction (domain) => règlesCRUD, à réutiliser dans plusieurs déclarations. Les verbes omis gardent les défauts français ; les règles explicites existantes restent acceptées. La locale n'influence jamais les droits.

Corrections de console ​

  • socketIoSource accepte le type réel de socket.io-client sans conversion. Socket.IO est utilisé uniquement comme dépendance de test de @sia-ui/api, pas de production.
  • TabsList conserve le défilement horizontal et masque le débordement vertical.
  • Icons fournit RefreshIcon, LinkIcon, ExternalLinkIcon, FileTextIcon, KeyboardIcon et LayersIcon.

Mettre à jour une application ​

Deux canaux restent disponibles à partir de la même implémentation :

CanalMise à jourChoix pertinent
Imports npm depuis @sia-ui/react-webMettre à jour la dépendance et son lockfile, puis valider l'applicationComposants partagés, peu de modifications locales
Fichiers copiés par le CLIsia-ui list --outdated, sia-ui update --dry-run, sia-ui update, puis sia-ui diff pour les fichiers conservésComposants que l'application personnalise et possède

La copie n'interdit pas les mises à jour : update remplace les fichiers intacts et protège ceux qui ont été retouchés. Elle n'est simplement pas déclenchée par pnpm update des paquets de fondations. Utiliser --force seulement après revue, car il écrase les retouches. doctor contrôle l'état du verrou après la mise à jour. Utiliser une version du CLI et un registre correspondant à la release souhaitée : un ancien CLI embarqué ne connaît pas les nouvelles entrées.

Pour DevHub, conserver la copie quand les composants locaux sont personnalisés ; préférer les imports npm pour les nouveaux usages qui n'ont pas besoin de retouche. Une migration complète est une décision séparée, avec vérification des styles, des imports et des parcours. Aucune mise à jour du dépôt DevHub n'est effectuée par cette livraison SIA UI.
